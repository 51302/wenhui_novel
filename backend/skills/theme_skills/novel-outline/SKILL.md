# 章节概要（剧情发展路线）规划

本 skill 是本项目章节概要生成的方法论层。后端已有 `generate_outline_with_ai` 与 `OUTLINE_SYSTEM_PROMPT / OUTLINE_USER_PROMPT_TEMPLATE`（conf/prompts.yaml）承载具体提示词，本 skill 约定"概要应该长什么样、怎么把大框演绎成章节"，供规划时执行与自检。

## 产出物定义

每章概要是一条「剧情发展路线」，用箭头串联关键事件：

```
主角偷袭天道教宗→夺取镇教之宝→被追杀→坠崖获机缘
```

- 格式：`事件→事件→事件`，箭头即因果链，每个事件必须有因有果。
- 字数：每章 150-400 字（硬下限 170 字含标点）。
- 章节名：贴合网文风格、能引起点开欲望、不剧透关键反转。

## 核心方法：以大框为骨架，动态填充血肉

用户给的【后续剧情大框】是唯一剧情边界，概要不是在"缩写"大框，而是在"演绎"大框：

1. 逐句拆解大框：把大框中每个事件/冲突/转折拆成独立章节事件节点，每个节点都有场景+动作+对话+情绪。
2. 因果补链：大框有跳跃（"获得机缘→成为天仙"）就补中间过程——如何发现→什么阻碍→怎么克服→什么代价→突破异象→周围人反应。
3. 角色视角填充：只写主角行动时，补配角反应、暗处观察者、敌方应对，同一事件多视角。
4. 情绪节奏填充：为每个事件标注情绪基调（紧张/愤怒/犹豫/决绝/惊喜/恐惧），保证章节有起伏。

## 一致性铁律

- 大框未提及的事件、转折、冲突、人物、地点、势力一律不得出现；只能在大框范围内补充细节。
- 角色、宗门、势力、地名、功法、法宝、物品必须已在【作品设定】或【已有章节概要】中记载，不得凭空发明；大框提及的新人物可安排登场，但不得引入设定外力量体系。
- 保持人物生死状态、修为等级、关系、因果与已有设定一致。
- 境界体系：严格使用【作品设定】中定义的境界词汇，禁止体系外词汇（练气/筑基/金丹/元婴/化神/渡劫/大乘等）。
- 相邻章节因果承接：第 N+1 章开头能衔接第 N 章结尾。
- 沿【故事线】主干推进：关键节点逐步覆盖，不跳过重大事件、不新增相悖支线。

## 单章概要要素（缺一即不合格）

- 场景感：具体地点、氛围、环境细节（雨夜古观/血腥气洞府/嘈杂坊市）。
- 动作细节：具体动作而非抽象概括——写"他拔剑刺出，剑光如虹，贯穿敌人咽喉"，不写"双方交战"。
- 对话暗示：至少一句有信息量的台词，展现性格或推进情节。
- 情绪弧线：写出人物当下的情绪变化，让读者感知心理。
- 感官锚点：至少一个感官细节（视/听/嗅/触）。
- 因果承接：事件有原因有结果，不孤立。
- 群像呈现：多人同场时每个有名角色有"动作+反应/台词"，禁止"众人震惊""众人哗然"一笔带过。
- 钩子收尾：每章结尾留悬念或危机，勾下一章。

## 剧情密度与群像配额

- 每章至少 4-6 个独立事件节点，禁止"主角修炼/思考/赶路"式空洞叙述。
- 冲突要有层次：小摩擦→升级→爆发→余波，每章至少一个情绪高点。
- 每 N 章中至少 40% 含群像戏（3+ 有名角色同场互动），每 N 章至少 1 章"配角主场章"。
- 配角要有存在感：有自己的判断、选择，甚至与主角分歧。

## 与题材层协作

题材层 skill（novel-xuanhuan 等）的读者承诺、反套路红线同样约束概要：概要中的爽点/冲突/代价要在题材允许的方向上；如玄幻的"获得必须有代价"、悬疑的"线索必须公平"、都市情感的"关系推进靠事件不靠误会"。规划概要前先确认作品题材对应题材 skill 的红线，避免概要级就埋下反套路雷。

## 交付自检（勾不上先改再交）

- [ ] 每章 ≥170 字、4-6 个事件节点，事件有画面感与情绪冲击？
- [ ] 全部发生在大框范围内，无新增人物/势力/地名/功法/体系？
- [ ] 境界体系使用作品设定词汇？
- [ ] 相邻章节因果衔接，第 N+1 章开头接得上第 N 章结尾？
- [ ] 每章含场景/动作/对话/情绪/感官/钩子六要素？
- [ ] 群像戏比例与配角主场章达标？
- [ ] 章节名贴网文风格且不剧透反转？
- [ ] 输出为 JSON 数组，长度严格等于请求章数，无额外文字？

## 输出要求

按后端约定输出：仅一个 JSON 数组，每个对象 `{"chapter_name": 章节名, "chapter_summary": 剧情发展路线概要}`，不要 markdown 代码块标记、不要任何其他文字。生成结果由后端校验字数（<170 字会被过滤）并写入缓存供正文生成消费。
